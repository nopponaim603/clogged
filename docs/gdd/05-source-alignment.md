## 1. ขอบเขตและกติกาอ่านเอกสาร

Google Doc นี้ใช้ชื่อเวอร์ชัน **A 0.2** และอธิบายการส่งหน่วยสำรวจ งานในฐาน ระบบวัน AP ความหิว D100 และเงื่อนไขชนะ

GDD ใน repo เป็นเอกสาร **Unity V2** ซึ่งยึดพฤติกรรมของระบบใน `Unity-Projects/Assets/V2/` เป็นหลัก เพราะมีการพัฒนาต่อจาก A 0.2 แล้ว รายการในไฟล์นี้จึงแยกเป็น:

- **ตรงกัน** — มีใน A 0.2 และ V2 เหมือนกัน
- **V2 ขยายจาก A 0.2** — ไม่มีข้อความขัดแย้งชัดเจน แต่เป็นระบบที่เพิ่มภายหลัง
- **แก้ไขแล้ว / ต้องนำไปใช้** — สเปกได้รับการยืนยัน แต่ implementation ใน Unity อาจยังรอแก้
- **รอคำอธิบายหรือชื่อผู้เล่น** — พฤติกรรมยังคงเดิม แต่คำเรียกหรือความหมายต้องทำให้ชัด

จนกว่าจะมีการตัดสินใจใหม่ ให้ถือ [Core Mechanics](01-mechanics.md) เป็นกติกาปัจจุบันของเกม และใช้ตารางความขัดแย้งด้านล่างเป็นรายการให้เจ้าของเกมตัดสิน

### 4.1 ความคลุมเครือภายใน Google Doc เอง

- ต้นทุนโบนัสส่งคู่ปรากฏทั้ง **+15** และ **+25**
- Hard Success ปรากฏทั้ง “โอกาสปลดล็อก / ดรอป” และ “ได้ชิ้นเมื่อ Hard Success”
- ข้อความเรื่อง Talent Dan ระบุเพิ่มโอกาสดรอป KEY/BOX แต่ก็ไม่มีสูตรหรืออัตราดรอป

ประเด็นเหล่านี้ควรแก้ในแหล่งต้นทางด้วย เพื่อไม่ให้เอกสารใน repo ถูกตีความต่างกันในรอบถัดไป

### 4.2 ระบบ Death / Missing / Lost Signal

ระบบนี้เป็น **สถานะเสียยูนิตถาวรภายใน run** ไม่ใช่สามสถานะแยกกัน:

1. **Death** — ชื่อสถานะที่เกมใช้งานในโค้ดปัจจุบัน ยูนิตเข้าสถานะนี้เมื่อ starvation stack ถึง 3 หลังจากนั้นรักษาไม่ได้ ทำงานไม่ได้ ส่งสำรวจไม่ได้ ได้รับ AP ใหม่ไม่ได้ และไม่กินอาหารอีก
2. **Missing** — ชื่อที่เคยใช้กับสถานะเดียวกันในสเปก โค้ด และเซฟเก่า ปัจจุบันคงชื่อเดิมไว้บางจุดเพื่อความเข้ากันได้ย้อนหลัง
3. **Lost Signal** — ชื่อเชิงเนื้อเรื่องที่สื่อว่ายูนิตขาดการติดต่อ ไม่ได้สร้างผลเชิงกลไกต่างจาก Death

Fumble ไม่ทำให้เกิดสถานะนี้ในกติกาปัจจุบัน ทุกคนที่เข้าทริปเป็น Hurt แทน ถ้าทั้งทีมอยู่ใน Death เกมประกาศ `LoseAllUnitsLost`; ชื่อนี้เป็นชื่อ outcome เดิมแต่หมายถึงทีมที่ไม่มีใครมีชีวิตตาม implementation ปัจจุบัน

### 4.3 ผล Talent Dan ต่อ KEY/BOX

สมมติ Dan อยู่ในทริปที่ให้ loot:

- Hard Success: คูณของหลักและ bonus loot ×2
- Regular: คูณของหลัก ×2
- Failure: คำนวณของหลักครึ่งหนึ่งปัดลงก่อน แล้วคูณ ×2
- Fumble: ไม่มี loot จึงไม่มีอะไรให้คูณ

หลังจากคำนวณ loot ปกติ KEY หรือ BOX จะถูกให้ตามกติกา Hard Success ของถ้ำแยกต่างหาก Dan จึงไม่ทำให้ได้ KEY/BOX มากกว่า 1 ชิ้น ไม่เพิ่มโอกาส Hard Success หรือ Jackpot และไม่ทำให้ชิ้นที่เก็บแล้วดรอปซ้ำ
